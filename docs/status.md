## 2026-11-12 演示运行（宣传片素材）

在隔离 dsh + 真实模型（deepseek-v4.1-flash）上用演示项目 tiny-todo（给命令行待办加截止日期）跑了三次 `taktflow-standard`：

- 第 1、2 次：评审节点的作者修订在长上下文时模型网关请求超时，节点诊断误报为“没调用 structured_output”。给模型提供方配置 `timeoutMs: 600000` 后不再超时。
- 第 3 次：3 小时 25 分钟里 45 次 Agent 会话、15 轮评审、提出 119 条问题、打回 2 次，跑完需求理解、系分、测分、对齐冻结，进入研发；第 2 个开发任务的代码评审里，作者回应没有与本轮问题逐条对应，节点直接失败，运行终止。

这几次暴露的问题：网关超时被误报；面板回答待办只记进事件、没有写进 `decisions/`，下游 PRD 节点看不到；AI 代答有自己的短超时；作者回应格式不对时整次运行失败而不是重试或升级；开发角色没有删除文件的工具；不同评审者的打分尺度不一致。
